RAG Collapse · HotpotQA · Round-0 Diversity

Seeding the loop with diverse wrong answers
to watch it collapse

A beginner-friendly guide to the diverse_synth experiment: how we use a strong language model to plant several different, believable wrong answers into a retrieval system on round 0 — so that we have something wide enough to actually measure "collapse" as the system feeds on its own output round after round.

01 — Background

What is "RAG collapse," in plain terms?

RAG stands for Retrieval-Augmented Generation. Instead of asking a language model a question from memory, you first retrieve a few relevant documents and paste them into the prompt, so the model answers from those documents. This is how most modern "chat with your docs" systems work.

Now imagine a feedback loop. The model reads some documents, writes an answer, and then that answer is turned into a new document and added to the pool that future questions retrieve from. Repeat this many times. This is what we call a recursive self-refinement loop — the model is increasingly reading its own past output instead of fresh, human-written text.

Step 1
Retrieve

Pull the top documents related to the question.

→
Step 2
Answer

The model answers using those documents.

→
Step 3
Condense

Turn the answer into a new "document."

→
Step 4
Feed back

Add it to the pool. Go to Step 1.

Over many rounds, something unhealthy happens: the answers stop being varied and all converge to the same text. The system loses variety and "locks in." That narrowing is collapse. It's the inference-time, retrieval-driven cousin of "model collapse" — the well-documented effect where AI systems trained on AI-generated data degrade.

Two things can go wrong, and they're different. (a) Concentration — the spread of answers narrows toward a single answer. (b) Shift — that single answer drifts away from the truth. This experiment is mostly about being able to see concentration happen, starting from a deliberately wide spread.
02 — The problem

Why the earlier HotpotQA runs didn't show much

HotpotQA is a question-answering dataset where each question has a known correct answer (the "gold" answer) and requires combining facts from two Wikipedia paragraphs. Because we know the gold answer, we can measure exactly how often the system is right or wrong — perfect for studying collapse.

To study collapse you need a starting spread to collapse from. If round 0 already has everyone agreeing on one answer, there's nothing to narrow — you can't watch a crowd disperse if they all started in the same spot. So we plant "distractor" documents on round 0: documents that confidently assert a wrong answer, to widen the initial range of answers.

The earlier attempts produced a starting spread that was barely wider than one answer — a measured diversity (distinct_answers) of about 1.3. Two root causes:

① A weak document writer

The documents were generated by a small local model (Qwen2.5-7B). Its fake documents were bland and unconvincing, so the answering model often ignored them and snapped back to gold.

② Uncoordinated wrong answers

The old rewrite mode corrupted each document independently. Independent guesses tend to land on the same most-obvious wrong answer — so the "distractors" weren't distinct from each other. No diversity.

The crux: ten documents that all say the same wrong thing give you a spread of one wrong answer, not ten. We needed wrong answers that are different from each other and believable.
03 — The idea

The diverse_synth approach

This experiment adds a new distractor-generation mode called diverse_synth ("diverse synthesis"). It fixes both root causes at once:

  • Use a strong model to write the fake documents (routed through an API — see §6), so they're convincing.
  • Coordinate the wrong answers so each planted document asserts a different, plausible wrong answer — guaranteeing variety on round 0.

Concretely: for a question whose gold answer is Newport, instead of three documents all nudging toward "Claremont," we plant three documents that each confidently argue for a distinct wrong answer — plus we keep at least one real document that still supports gold. The round-0 spread looks like this:

kept · real docThe county seat is Newport, established 1827…
distractor 1Records indicate the seat is Claremont…
distractor 2The administrative center is Lebanon…
distractor 3Officially, the county seat is Keene…
Now round 0 has four distinct candidate answers in play (Newport, Claremont, Lebanon, Keene). That's a real spread — and over the next rounds we can watch the loop concentrate back down to one. That narrowing is the data we're after.

Where this idea comes from. It sits in a gap between two lines of published work:

  • Distractor generation (e.g. Bitew et al. 2023; PlausibleQA) shows language models are good at inventing plausible wrong answers — but that work is about building quiz questions, not studying loops.
  • RAG poisoning (PoisonedRAG, 2024) plants malicious documents to force one specific wrong answer — but it's single-target, the opposite of diverse.

We borrow the "make plausible wrong answers" technique but aim for many distinct ones, to seed diversity rather than to attack a single target.

04 — How it works

The two-phase generation, step by step

The whole thing happens once, before the loop starts, and uses exactly two batched calls to the strong model. "Batched" means we send all questions together in one request for speed.

Phase A
Propose K distinct wrong answers

For each question, ask the model: "Give me K plausible answers of the same type as the gold answer, but all wrong and all different from each other." A helper (choose_distinct_substitutes) then filters them so none equals the gold, none appears in the question, and no two are duplicates.

→
Phase B
Write one real-looking doc per wrong answer

For each distinct wrong answer, ask the model to write a natural encyclopedia-style document as if that answer were true. We reuse the exact same prompt used to write normal documents — so a distractor reads like any other generated document, not an obviously tampered one.

Each planted document records what wrong answer it carries, so later analysis knows the ground truth of every planted error. A safety check ("gold-leak guard") makes sure the fake document didn't accidentally still mention the correct answer; if it did, we append an explicit wrong-answer sentence to keep the document genuinely misleading.

How many documents get corrupted? (the K knob)›

You don't set K directly. You set --distractor-fraction (a number between 0 and 1), and K is computed as roughly that fraction of the retrieved documents. For example, with 10 retrieved documents and --distractor-fraction 0.7, about 7 become distinct distractors and ~3 stay as real documents. This keeps the new mode consistent with the older distractor modes — no extra flag to learn.

Why reuse the normal document prompt instead of a special "lie" prompt?›

Two reasons. First, the model is simply given a wrong answer and asked to write about it — it isn't told "lie," which avoids refusals. Second, using the identical prompt means a distractor document is stylistically indistinguishable from a genuine generated document, so the experiment isn't accidentally measuring "the model spots weird-looking text."

05 — A subtle but important fix

Keeping at least one correct document alive

There's a trap. The code that picks which documents to corrupt prefers documents that contain the gold answer (because corrupting an irrelevant document would be pointless). But if the fraction is high, that preference could corrupt every gold-bearing document — erasing the correct answer from the context entirely.

If gold disappears from round 0, you can no longer see whether the loop collapses toward or away from the truth — you've removed the most interesting outcome.

So diverse_synth adds a rule: if the selection would consume all gold-bearing documents, drop one so at least one correct document survives. The result is exactly the spread we want — one anchor of truth plus several distinct wrong answers — and it's recorded honestly (the document count corrupted goes down by at most one, and a note is logged).

This matches the choice made during planning: "mix gold + distinct distractors", rather than wiping out gold completely.
06 — The strong model

"Model x" and how it's plugged in (LiteLLM)

The answering model still runs on the lab's own GPU servers (vLLM). But the document writer can now be swapped for a strong commercial-grade model accessed over an API. That routing goes through two existing pieces:

LiteLLM

A small library that gives one uniform way to call many different model providers. The repo's ProprietaryLLM class wraps it.

The "keymaker" proxy

UMass's gateway (thekeymaker.umass.edu) that the API calls go through. You authenticate by setting an API_KEY environment variable.

To turn it on you pass --doc-model-mode api and name the model with --doc-model-name openai/<model>. The new --doc-model-mode flag defaults to server, so every existing script keeps working untouched.

Which model is "model x"? It's just a runtime argument. We're currently using azure/gpt-5-mini (verified working through keymaker), with the answering model fixed to qwen2.5-14b. openai/claude-sonnet-4-6 is a fine alternative.
Reasoning-model gotcha (verified). gpt-5-mini is a "reasoning" model, so two things must be set or the experiment silently breaks: (1) it refuses the top_p / custom temperature settings — the code now auto-strips those (litellm.drop_params=True); and (2) it spends part of the token budget on hidden reasoning, so a small document budget returns empty documents — api-mode runs default --doc-max-tokens to 2048. Both are handled for you; just be aware if you change them.
07 — Metrics

What we actually measure each round

These metrics already existed in the evaluation code — the new mode plugs straight into them with no changes. For each round, over all the runs of a question:

MetricWhat it means (beginner version)
distinct_answersThe headline signal. How many different answers appear this round. High at round 0 (wide spread), then we expect it to fall as the loop collapses.
gold_match_rateFraction of answers that are correct. Tracks whether the system recovers to the truth or drifts away from it.
distractor_adoption_rateFraction of answers that adopted one of the planted wrong answers. Shows the distractors are actually influencing the model.
offtarget_rateFraction of answers that are neither gold nor any planted wrong answer — i.e. the model invented a new wrong answer on its own.
distractor_retrieval_conditionWhether a planted document was actually retrieved into the context this round (a sanity check that the distractor is reachable).
The story we hope to tell: round 0 has high distinct_answers (several wrong answers + gold), and over the following rounds it shrinks as the loop concentrates — visible collapse, finally measurable because we engineered a wide enough starting point.
08 — How to run it

Running the experiment

A single run

# strong API model writes the distractor docs; answerer stays on the vLLM server
API_KEY=... python hotpot_pipeline.py \
  --vllm-api-base http://<answerer>/v1 --model-name qwen2.5-14b \
  --doc-model-mode api --doc-model-name openai/claude-sonnet-4-6 \
  --distractor-mode diverse_synth --distractor-fraction 0.7 \
  --gt-file hotpot_dev_fullwiki_v1.json --pipeline-variant search \
  --max-questions 50 --num-runs 10 --seed 42 --output-path out_f0.7.json

A "dose-response" sweep (recommended)

Run several fractions at once to see how more distractors changes the picture. Fraction 0 is the clean baseline (no distractors) and is always included for comparison.

# in base_hotpotqa_distractors/run_sweep.sh
DOC_MODEL_MODE=api  DOC_MODEL=openai/claude-sonnet-4-6 \
DISTRACTOR_MODE=diverse_synth  FRACTIONS="0 0.3 0.5 0.7"  API_KEY=... \
  sbatch run_sweep.sh
# then compare_sweep.py prints a per-round table including distinct_answers

A quick smoke test first

Before a big run, sanity-check on 1–2 questions: --max-questions 2 --num-runs 4 --num-iterations 3. Then open the output JSON and confirm each question lists several distinct planted answers, and that round 0 still includes a real gold document.

Never commit your API_KEY. It lives only in your environment for the run.
09 — What success looks like

How we'll know it worked

≈ 3–4round-0 distinct answers

At fraction 0.7, round 0 should show several distinct answers — far above the old ~1.3.

↓diversity over rounds

distinct_answers should decrease across rounds — the collapse signal.

vs.baseline & old modes

diverse_synth should start wider than rewrite/substitution and the no-distractor baseline.

If round 0 is wide and the following rounds narrow, we've turned "collapse" from something we assert into something we can plot.
