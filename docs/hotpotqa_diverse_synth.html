01 — Background

What is "RAG collapse," in plain terms?

RAG stands for Retrieval-Augmented Generation. Instead of asking a language model a question from memory, you first retrieve a few relevant documents and paste them into the prompt, so the model answers from those documents.

Now imagine a feedback loop. The model reads some documents, writes an answer, and then that answer is turned into a new document and added to the pool that future questions retrieve from. Repeat many times — the model increasingly reads its own past output instead of fresh, human-written text.

Step 1
Retrieve

Pull the top documents related to the question.

→
Step 2
Answer

The model answers using those documents.

→
Step 3
Condense

Turn the answer into a new "document."

→
Step 4
Feed back

Add it to the pool. Go to Step 1.

Over many rounds, the answers stop being varied and converge to the same text. That narrowing is collapse — the inference-time, retrieval-driven cousin of "model collapse."

Two distinct failure modes. (a) Concentration — the spread of answers narrows toward a single answer. (b) Shift — that answer drifts away from the truth. As you'll see in §11, our distractors mostly drive shift so far; the new per-run change (§7) targets concentration.
02 — The problem

Why the earlier runs didn't show much

HotpotQA is a multi-hop QA dataset where each question has a known correct ("gold") answer. Its context is the introductory paragraph of Wikipedia articles — in the distractor setting, 2 gold + 8 TF-IDF-selected Wikipedia paragraphs. Because we know the gold answer, we can measure exactly how often the system is right or wrong.

To study collapse you need a starting spread to collapse from. So we plant "distractor" documents on round 0 that confidently assert a wrong answer. The earlier attempt produced a spread barely wider than one answer (distinct_answers ≈ 1.3), for two reasons:

① A weak document writer

Documents came from a small local model (Qwen2.5-7B) — bland, unconvincing fakes the answerer often ignored.

② Uncoordinated wrong answers

The old rewrite mode corrupted each doc independently, so the fakes converged on the same obvious wrong answer. No variety.

The crux: ten documents that all say the same wrong thing give a spread of one wrong answer, not ten. We need wrong answers that are different from each other and believable.
03 — The idea

The diverse_synth mode

The current experiment adds a distractor-generation mode called diverse_synth ("diverse synthesis"), which fixes both root causes:

  • Use a strong model (over an API) to write convincing fake documents — see §9.
  • Coordinate the wrong answers so each planted document asserts a different, plausible wrong answer — guaranteeing variety on round 0.

It sits in a gap between two lines of published work: distractor generation (Bitew et al. 2023; PlausibleQA) shows LLMs invent plausible wrong answers — but for quiz-building, not loops; RAG poisoning (PoisonedRAG, 2024) plants docs to force one target answer — single-target, the opposite of diverse. We borrow "make plausible wrong answers" but aim for many distinct ones to seed diversity.

05 — Building a distractor

How one distractor document is built

For each question, generation happens once (before the loop) in exactly two batched calls to gpt-5-mini. The code path is DistractorController._apply_diverse_synth.

Phase A
Propose K distinct wrong answers

One call asks gpt-5-mini for K plausible answers of the same type as the gold answer, all wrong and all different. K ≈ the number of docs to corrupt.

→
filter
Enforce distinctness

choose_distinct_substitutes drops any candidate equal to gold, overlapping gold, appearing in the question/context, or a duplicate of one already chosen.

→
Phase B
Write a Wikipedia-style doc per answer

One call per distinct wrong answer asks for a Wikipedia lead paragraph asserting that answer — so it blends in with the real Wikipedia paragraphs around it.

How we ensure the documents give different answers

Distinctness is enforced at the entity level, before any document is written:

  • Phase A explicitly requests mutually distinct wrong answers of the same type as gold.
  • choose_distinct_substitutes then dedupes on a normalized form (lowercased, articles/punctuation stripped) and validates each candidate — so two docs can never carry the same wrong answer, and none accidentally equals or contains the gold.
  • Each corrupted doc is assigned one entity (subs[j]); they only repeat if the model returned fewer distinct candidates than docs (rare — in practice it returns 6–7 cleanly distinct).
  • Every assignment is recorded as {doc_id, injected_entity, status} in the question's initial_distractor log, so the ground truth of each planted error is known.

Wikipedia style, with anti-refusal framing

The Phase-B prompt (get_create_distractor_document_conversation) asks for a neutral, factual Wikipedia lead paragraph and frames the task as an educational media-literacy benchmark (text used to teach people to verify claims against reliable sources). This stops a strong model from refusing, and tells it not to mention the real answer or add disclaimers.

What if the model leaks the gold or refuses?

Each finished document is checked: it is accepted only if it asserts the assigned wrong answer and omits the gold. Otherwise it is replaced with a clean templated assertion (fallback_distractor_paragraph) — so a refusal or a gold-leak never gets seeded. The per-doc status is then ok or fallback_template.

How many documents get corrupted? (the K knob)›

You don't set K directly — you set --distractor-fraction (0–1) and K ≈ that fraction of the 10 round-0 docs, capped to the 8 non-gold slots (the 2 gold paragraphs are never touched — §8). At 0.7, ~7 of the 8 distractor slots become distinct wrong-answer docs. No separate K flag.

07 — Per-run subsets ★ newest change

Making the round-0 answers actually diverse

The first smoke revealed a subtlety. We generated 6–7 beautifully distinct distractors per question — but the answers weren't diverse. Across all runs of a question, qwen gave the same answer (e.g. "Uglies" on all 5 runs of the Animorphs question), and distinct_answers actually fell from 2.43 → 1.29 (see §11).

Why: every run of a question saw the same context (all distractors at once). Given several competing wrong answers in one prompt, the answerer just concentrates on the single most salient one — and does so consistently. The diversity lived in the distractor set, never in the answers.

The fix (Option A, --distractor-per-run): instead of every run seeing all distractors, each run sees the clean/gold docs plus one rotating distractor. Run 1 gets distractor #1, run 2 gets #2, and so on (per_run_doc_subsets, run r → distractor r mod D). Different runs are pulled toward different wrong answers, so the round-0 answer distribution is genuinely wide — which is the spread collapse can then narrow.

Before (shared context)

All 5 runs see {gold + 6 distractors} → all 5 answer "Uglies". distinct_answers ≈ 1.

After (per-run subset)

Run 1 sees {gold + "Hunger Games"}, run 2 {gold + "Divergent"}, … → answers span several candidates. distinct_answers ↑.

It's available via --distractor-per-run, but the current oz03-hub-style runs leave it OFF (shared context — all runs see the same 2 gold + injected distractors), to stay faithful to the standard runs. The focus there is multi-round collapse across the 3 variants rather than across-run round-0 spread. Flip it on later if you want to revisit round-0 diversity.

08 — Never corrupt gold

The 2 gold paragraphs stay untouched

In the native distractor setting each question starts with 2 gold + 8 distractor paragraphs. We inject our wrong-answer documents only into the 8 non-gold slots — the 2 gold paragraphs are never altered. This matches the other HotpotQA experiments (you keep the gold context and vary the distractors) and keeps the experiment clean: gold is always reachable, so we can see whether the loop drifts toward or away from it.

Mechanically (--distractor-avoid-gold): a doc counts as gold if it is tagged gold=True (native supporting-fact paragraph) or it contains the gold answer string. select_distractor_indices excludes all such docs and then picks randomly (seed 42) from the rest. If a question somehow has no non-gold docs, nothing is corrupted (status no_docs).

Earlier the selector preferred corrupting gold-bearing docs (to force an answer-relevant flip). That's the opposite of what we want here, so this experiment turns it off and protects gold instead.
09 — The strong model

gpt-5-mini via LiteLLM / keymaker

gpt-5-mini is used only to write the round-0 distractor documents — not the per-round AI docs (those come from the qwen2.5-7b-docgen server). It is reached through two existing pieces — LiteLLM (a uniform interface to many providers, wrapped by the repo's ProprietaryLLM) and the keymaker proxy (thekeymaker.umass.edu, authenticated with an API_KEY read from .env).

It's wired via a dedicated, decoupled model: --distractor-model-mode api --distractor-model-name azure/gpt-5-mini builds a separate distractor_llm for round-0 only, while --doc-model-* (the qwen2.5-7b-docgen server) drives every round's synthesis. The distractor model needs no GPU (it's an API call).

Reasoning-model gotchas (verified, now handled). (1) gpt-5-mini rejects top_p and custom temperature → the code sets litellm.drop_params=True to strip them automatically. (2) It spends part of the token budget on hidden reasoning, so a small budget returns empty documents → api mode defaults --doc-max-tokens to 2048. Both are automatic; just be aware if you change them.
10 — Metrics

What we measure each round

All metrics are computed on the answerer's answers (qwen's runs), per question per round, for questions with an eligible distractor record:

MetricMeaning
distinct_answersCount of distinct answers across the runs of a question — the diversity signal (capped by num_runs).
distractor_adoption_rateFraction of answers that adopted one of our seeded wrong answers — the direct causal link to the distractors.
gold_match_rateFraction correct — recovery / drift from truth.
offtarget_rateFraction off both gold and every seeded entity (the model invented a new wrong answer).
distractor_retrieval_conditionWhether a planted doc was actually in the round's context (a reachability sanity check).

The dose-response table (compare_sweep.py) prints these per fraction; the r0_dist/rF_dist columns are mean distinct_answers at round-0 / final round. Attribute diversity to the distractors by the f=0 vs f>0 delta.

11 — First smoke results

What the first run actually showed

1 round, 10 questions (7 eligible; 3 skipped as yes/no), qwen2.5-14b + gpt-5-mini, before the per-run change of §7:

round-0 metricf = 0 (clean)f = 0.7 (diverse_synth)
gold_match0.370.11
distractor_adoption00.69
offtarget0.630.20
distinct_answers2.431.29

✅ What worked

Generation was excellent (6–7 distinct, on-type, believable distractors per question; fallback handled refusals). And the distractors were causally powerful: adoption 0.69, gold crashed 0.37 → 0.11. The misinformation clearly drives the model.

⚠️ The surprise

Diversity went down (2.43 → 1.29). With all distractors in one shared context, qwen concentrated on a single wrong answer per question — a clean demonstration of shift, but not the across-run spread we wanted. This motivated §7.

Next: re-run the smoke with --distractor-per-run (now default-on). Expectation: distinct_answers at f=0.7 rises above the f=0 baseline, because each run is pulled toward a different seeded answer. Two notable single-question cases: one question the model fully resisted (answered gold despite 7 distractors); another it took a numeric distractor ("4,000") over the gold "3,677 seated".
12 — How to run it

Running the experiment

The full experiment (one command)

# on a Unity login node, after pulling. Starts the qwen2.5-14b answer server + the
# qwen2.5-7b-docgen server, runs all 3 variants x 4 fractions, then auto-reaps.
# API_KEY (for gpt-5-mini distractors) is read from .env at the repo root.
bash base_hotpotqa_distractors/oz03_sweep.sh

Defaults: VARIANTS="search hybrid replace_one", NUM_ITERATIONS=3, MAX_Q=10, FRACTIONS="0 0.3 0.5 0.7", SEED=42, DISTRACTOR_AVOID_GOLD=1, NATIVE_FILE=$SCR/hotpot_dev_distractor_v1.json (override any via env).

A single run (what the script expands to)

API_KEY=... python hotpot_pipeline.py \
  --vllm-api-base http://<answer>/v1 --model-name qwen2.5-14b \
  --doc-model-mode server --doc-vllm-api-base http://<docgen>/v1 --doc-model-name qwen2.5-7b-docgen \
  --distractor-model-mode api --distractor-model-name azure/gpt-5-mini \
  --initial-docs native_distractor --native-hotpot-file hotpot_dev_distractor_v1.json \
  --distractor-mode diverse_synth --distractor-fraction 0.7 --distractor-avoid-gold \
  --gt-file hotpot_dev_fullwiki_v1.json --pipeline-variant hybrid --num-synth-docs 10 --num-db-docs 0 \
  --max-questions 10 --num-runs 10 --num-iterations 3 --seed 42 --output-path out.json
Never commit your API_KEY — it lives only in .env / the environment.
